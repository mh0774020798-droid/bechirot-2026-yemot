# קו עדכוני בחירות 2026 — הוראות התקנה

## הפריסה הפעילה

Google Apps Script ו־Cloudflare כבר נפרסו וחוברו. כתובת התפריט הפעילה:

[פתיחת תפריט הבחירות](https://elections-2026-yemot.mh0774020798.workers.dev/menu)

להתקנה בקו, צור שלוחה פנויה **9** עם תתי־שלוחות **1–5**, והעתק אליהן את קובצי `ext.ini` שבתיקיית `yemot/9`. הקבצים במאגר כבר כוללים את כתובת ה־Worker הפעילה, ולכן אין צורך להחליף בהם כתובת. `wrangler.toml` כולל את הגדרות הפריסה הפעילה. שינוי מספר השלוחה מחייב להתאים גם את `YEMOT_ROOT` ב־Worker.

השלבים בהמשך מסבירים גם כיצד ליצור פריסה חדשה בעצמך. לאחר התקנת השלוחות נדרשת בדיקת חיוג אמיתית לכל חמשת המקשים וחזרה לתפריט.


החבילה מפעילה קו טלפוני במבנה שביקשת: ימות המשיח פונה ל־Cloudflare Worker, ה־Worker פונה ל־Google Apps Script, והסקריפט קורא את מקור הבחירות ומחזיר פקודות הקראה לימות. התפריט טלפוני בלבד; אין אתר ניהול, עיצובים או צורך במפתח של שירות הקראה חיצוני.

ברירת המחדל היא **שלוחה חדשה `/9`**, לצד קו החדשות הקיים שלך. אין בקוד פקודות לכתיבה לקו, מחיקת קבצים או שינוי השלוחות הקיימות. קובצי `ext.ini` מיועדים להעתקה לשלוחה פנויה שתבחר.

## מה יש בקו

| מקש בתפריט הבחירות | תוכן | הכתובת ב־Worker |
|---|---|---|
| 1 | תקציר עדכני | `/summary` |
| 2 | אחוזי הצבעה | `/turnout` |
| 3 | מדגמים | `/exitpolls` |
| 4 | תוצאות אמת | `/results` |
| 5 | רשימות ואותיות הפתק | `/parties` |
| 0 או 9 | חזרה לתפריט הקודם | דרך התפריט |

בסיום כל הקראה חוזרים לתפריט הבחירות. המקור עצמו קובע את התוכן הזמין בכל שלב של יום הבחירות. לפני שיש מדגמים או תוצאות, מושמעת הודעת ההמתנה שהמקור מספק.

## 1. Google Apps Script

1. צור **פרויקט Apps Script חדש**. השאר את פרויקט החדשות הקיים כפי שהוא.
2. החלף את תוכן `Code.gs` בתוכן הקובץ `Code.gs` שבחבילה, ושמור.
3. בחר בעורך את הפונקציה `runSelfTests` והפעל. בתוצאה אמור להופיע `"ok":true`.
4. הפעל גם את `testLiveSources` ואשר את הרשאות הגישה לרשת של Google. היא בודקת את חמש כתובות המקור ומכינה את המטמון לקריאות הראשונות. בתוצאה נדרשים `"ok":true` וחמישה סעיפים עם `"ok":true`.
5. לחץ **פריסה → פריסה חדשה → אפליקציית אינטרנט**.
6. בחר **ביצוע בתור: אני** ו־**למי יש גישה: כל אחד / Anyone**. גישה המחייבת חשבון Google לא מתאימה לחיבור לימות.
7. פרוס והעתק את הכתובת המסתיימת ב־`/exec`. אין להשתמש בכתובת `/dev`.

`appsscript.json` מצורף למי שמגדיר את המניפסט ידנית: אזור הזמן הוא `Asia/Jerusalem`, סביבת הריצה היא V8, והרשאת OAuth היחידה היא גישה לבקשות רשת. בהדבקה רגילה של `Code.gs`, Google יכול לזהות את ההרשאה אוטומטית.

## 2. Cloudflare Worker

1. צור Worker חדש ונפרד עבור הבחירות.
2. הדבק בו את כל תוכן `worker.js` שבחבילה.
3. בראש הקובץ החלף **רק את הטקסט** `PASTE_GOOGLE_APPS_SCRIPT_EXEC_URL_HERE` בכתובת `/exec` שקיבלת מ־Google. השאר את המרכאות.
4. השאר `DEFAULT_YEMOT_ROOT = '/9'` אם התקנת את הקו בשלוחה 9. אם בחרת שלוחה אחרת, הגדר כאן את הנתיב המלא שלה, למשל `/7` או `/8/9`.
5. שמור ופרוס, והעתק את כתובת ה־Worker, למשל `https://elections-example.workers.dev`.

אפשר לחלופין להגדיר משתני Worker בשם `GOOGLE_SCRIPT_URL` ו־`YEMOT_ROOT`; כשהם קיימים הם גוברים על הקבועים בקובץ. `wrangler.toml` מצורף לשימוש ב־Wrangler, אך אין צורך ב־Wrangler בהתקנה דרך האתר.

## 3. השלוחות בימות המשיח

1. בחר שלוחה פנויה עבור תפריט הבחירות. בדוגמאות זו שלוחה **9**.
2. צור תחתיה את תתי השלוחות **1, 2, 3, 4, 5**.
3. בתיקיית `yemot/9` שבחבילה יש קובץ `ext.ini` לתפריט ועוד קובץ בכל תת־שלוחה. העתק כל קובץ לשלוחה המתאימה במערכת שלך.
4. בכל ששת הקבצים החלף את `https://elections-2026-yemot.mh0774020798.workers.dev` בכתובת ה־Worker שלך. **שמור את הסיומת השונה בכל שלוחה**: `/menu`, `/summary`, `/turnout`, `/exitpolls`, `/results`, `/parties`.
5. אם השתמשת בשלוחה אחרת, העתק את תוכן תיקיית `9` אל השלוחה שבחרת, וודא שהנתיב בקבוע `DEFAULT_YEMOT_ROOT` או במשתנה `YEMOT_ROOT` מתאים לה.

לדוגמה, ההגדרות של תפריט הבחירות כוללות:

```ini
type=api
api_link=https://elections-2026-yemot.mh0774020798.workers.dev/menu
api_url_post=yes
api_hangup_send=no
```

ובשלוחה 9/4, שלוחת תוצאות האמת:

```ini
type=api
api_link=https://elections-2026-yemot.mh0774020798.workers.dev/results
api_url_post=yes
api_hangup_send=no
```

מומלץ להעתיק את **כל** הקובץ המצורף, הכולל גם את הגדרות הקול וצמצום פרטי המתקשר הנשלחים. אין צורך ב־`api_000`, בהקלטת תפריט או בקובץ `M1000`: השרת מחזיר בקשת `read` המקריאה את התפריט ואוספת את המקש.

## 4. בדיקות לאחר הפריסה

בצע את הבדיקות הבאות לפני הפניית המאזינים לשלוחה:

| בדיקה | התוצאה הנדרשת |
|---|---|
| פתיחת `WORKER/health` | JSON עם `"ok":true` |
| פתיחת `WORKER/menu` | תשובת טקסט שמתחילה ב־`read=t-` |
| פתיחת `WORKER/menu?election_choice=4` | `go_to_folder=/9/4`, לפי נתיב השלוחה שבחרת |
| פתיחת כל אחת מחמש כתובות התוכן | תשובה שמתחילה ב־`id_list_message=t-` ומסתיימת ב־`&go_to_folder=/9` |
| חיוג לקו וכניסה לתפריט | הקראת התפריט וקבלת בחירת מקש |
| הקשת 1, 2, 3, 4, 5 בנפרד | התוכן המתאים וחזרה לתפריט הבחירות |
| הקשת 0 | חזרה לתפריט שמעל שלוחת הבחירות |

`WORKER` הוא כתובת ה־Worker שלך ללא לוכסן בסוף. לדוגמה `https://elections-example.workers.dev/health`.

`ok:true` ב־`/health` מאשר שה־Worker הצליח לתקשר עם הסקריפט. הוא **אינו** מאשר שהנתונים במקור התעדכנו עכשיו. בשדות `topics` ניתן לראות אם יש עותק במטמון וכמה שניות חלפו מאז שהתקבל. גם הודעת תקלה למאזין מתחילה ב־`id_list_message`, לכן קרא את התוכן בבדיקת הדפדפן ולא רק את תחילת השורה.

## זמינות, מהירות ועדכון

- נתונים נמשכים בעת כניסה לשלוחת תוכן. אין צורך בטריגר, תזמון Cloudflare, Google Drive או טוקן ניהול של ימות.
- תשובה תקינה נשמרת ל־30 שניות כדי להקטין עומס. אחרי זמן זה השיחה הבאה מנסה לרענן אותה. זהו זמן המטמון של החיבור; קצב עדכון הנתונים עצמם תלוי במקור.
- אם הרענון נכשל, ניתן להשמיע עותק שהתקבל לפני עד חמש דקות, עם הודעה מפורשת שמדובר בעותק קודם. עותק ישן יותר אינו מושמע. גיל העותק מתייחס לזמן קבלתו אצלנו, ולא לזמן פרסום הנתונים במקור.
- אם אין עותק זמין או ש־Google לא עונה בתוך 15 שניות, מושמעת הודעת תקלה וחוזרים לתפריט. בבדיקה שלנו מקור התוכן ענה בתוך כ־7–8 שניות; זמני Google ו־Cloudflare לאחר הפריסה עשויים להוסיף לכך. גישה ראשונה לשרת רדום עלולה להיכשל ולדרוש ניסיון חוזר.
- המטמון של Google הוא שירות זמני והוא עשוי להתרוקן מוקדם. במקרה כזה מתבצעת משיכה חדשה. מכסות Google ו־Cloudflare עדיין חלות על הפרויקט ועל החשבון.
- אין בקוד חישוב עצמאי של מנדטים או שילוב תוצאות היסטוריות. התוכן מגיע כפי שמספק מקור הבחירות, לאחר התאמה לפרוטוקול ההקראה.
- טקסט ארוך מחולק למקטעים קצרים בלי לקצר את תוכן העדכון. נקודות, מקפים ותווי בקרה מותאמים לפרוטוקול; שברים עשרוניים מוקראים עם המילה "נקודה".
- הקרדיט למקור נשמר בהקראה. מספרי טלפון, טוקנים ופרמטרי ניהול אינם מועברים למקור הנתונים.

## בדיקות הקוד המצורפות

נדרש Node.js בגרסה 20 ומעלה; אין תלות בחבילות npm חיצוניות.

```bash
npm test
npm run test:live
npm run test:deployed
```

`npm test` בודק את קוד Google ואת ה־Worker, כולל סימולציה של מסלולי השיחה, GET ו־POST, בחירת מקשים, נתיבים מקוננים, מטמון, תקלות תקשורת, תשובות HTML/JSON שגויות, פיצול טקסט ארוך והגבלת זמן. `npm run test:live` קורא את חמש הכתובות החיות ומזין את התשובות לאותו קוד בסימולציה מקומית.

`npm test` משתמש בהדמיה של שירותי Google וב־Node עבור ה־Worker. בנוסף בוצעו 25 בדיקות HTTPS של הפריסה הפעילה באמצעות `npm run test:deployed`. בדיקות אלה אינן כוללות אימות של מנוע ההקראה בשיחת טלפון אמיתית. תוצאות הבדיקות שבוצעו מצורפות ב־`TEST-REPORT-HE.md` ובתיקיית `evidence`.

## אם משהו לא עובד

| סימפטום | מה לבדוק |
|---|---|
| `/health` מחזיר 503 | כתובת `/exec`, הרשאת גישה של "כל אחד", ופריסה חדשה לאחר שינוי קוד |
| התפריט עובד אך התוכן נכשל | הפעל `testLiveSources` בעורך Google ובדוק את חמש התוצאות |
| חוזרים לשלוחה הלא נכונה | התאמה בין מיקום השלוחות לבין `YEMOT_ROOT` ב־Worker |
| אין תשובה או מוצג מסך התחברות | פריסת Google ציבורית וביצוע בתור בעל הפרויקט |
| שינוי בסקריפט לא מופיע בקו | פריסה → ניהול פריסות → עריכה → גרסה חדשה → פריסה |
| `runSelfTests` עובר אך שיחת ניסיון נכשלת | בדוק גם את הפריסה החיה, הגדרות `ext.ini` והקראת התוכן בימות |
